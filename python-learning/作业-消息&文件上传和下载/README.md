# 消息 & 文件上传和下载

## 需求
- 客户端定义 `send_data(conn, content)` 发消息、`send_file(conn, file_path)` 发文件、`run()` 完成逻辑；
  解决粘包、循环接收、避免信息接收不完整；发送三类信息：**消息 / 文件 / close**，直到 close 才关连接。
- 服务端接收客户端连接后可一直收内容；该客户端断开后能继续接收其他客户端；
  定义 `recv_data(conn)`、`recv_file(conn, ...)`、`run()`。
- 附加：服务端也能向客户端发消息/文件（协议对称化）。

## 文件
| 文件 | 说明 |
|---|---|
| `file_protocol.py` | 公共协议（收发帧、解决粘包），客户端服务端共用 |
| `upload_client.py` | 客户端：`send_data` / `send_file` / `run` |
| `upload_server.py` | 服务端：`recv_data` / `recv_file` / `run`，控制台也能下发 |

## 协议（解决粘包）
每一帧 = `1 字节类型` + `8 字节长度(大端)` + `负载`：
- `M` 消息；`F` 文件（负载 = 文件名长度+文件名+文件内容）；`C` close。

收的时候先读类型和长度，再按长度把负载读满，所以多条数据粘在一起也能正确拆开。

## 运行
```bash
python upload_server.py [端口] [保存目录]     # 默认 9200，保存到 ./uploads
python upload_client.py 127.0.0.1 9200
```
客户端交互：直接敲一行 = 发消息；`send 文件路径` = 发文件；`close` = 关闭链接；`quit` = 直接退出。
服务端控制台：敲一行 = 广播消息给所有客户端；`sendfile 路径` = 给所有客户端发文件。

## 自测结果
- 客户端上传消息 + 文件，服务端保存的内容与上传文件字节完全一致；
- 客户端发 `close` 后服务端回执“再见”并关闭链接；
- 服务端控制台能把消息和文件下发给客户端（协议对称化）——全部通过。
